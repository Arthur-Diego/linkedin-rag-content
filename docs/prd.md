# PRD — Automated LinkedIn content pipeline about RAG

> Approved 2026-08-09 (autonomous mode delegated by the owner).

## Problem

Maintaining a consistent technical presence on LinkedIn requires writing quality
posts several times a week — topic research, copy, image, and publishing at the
right time. Done manually, the process is irregular and ends up abandoned.

## Users

- **Owner** (Arthur Diego): sole user. Wants to publish technical content about RAG
  (Retrieval-Augmented Generation) on his personal profile 3x/week, with near-zero
  effort and zero cost.

## Goal

A 100% automated, free pipeline that, 3x per week:
1. Selects the next post from a queue of RAG content.
2. Renders a technical card image for the post.
3. Publishes to LinkedIn via the official API (or, with no token configured,
   delivers the finished post as a draft in a GitHub issue).

## Scope

- Post queue versioned in git (markdown + frontmatter), pre-generated by Claude Code.
- Local image rendering (Pillow) — card with title and bullets.
- Publishing to the personal profile via the LinkedIn Posts API (`w_member_social`).
- Scheduling via GitHub Actions cron (Mon/Wed/Fri).
- Draft mode (fallback without a token): artifacts in `out/` + a GitHub issue.
- Queue replenishment: documented prompt for generating new posts with Claude Code.

## Out of scope

- Multiple social networks; LinkedIn company pages.
- Engagement analytics.
- Paid AI image generation (Napkin AI, DALL-E, etc.).
- Web interface/dashboard.

## Expected outcome

Starting today, with the queue stocked (~3 weeks of content), the owner's LinkedIn
receives 3 technical posts per week with no manual intervention — at zero financial
cost (GitHub Actions on a public repo + LinkedIn's free API).
